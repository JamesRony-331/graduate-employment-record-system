# 统一账号与控制器合并

现在只有 SysUserController，统一以 /sys-user 开头。UserController 已移除。学生资料仍保存在 student，由 UserMapper 与 StudentService 处理；清除密码映射及登录职责，保留新增/查询/资料修改业务和 addStudent 的 void 签名。

## 接口

| 方法及路径 | 身份 | 用途 |
| --- | --- | --- |
| POST /sys-user/login | 无需登录 | 学生和教职工统一认证 |
| POST /sys-user/register | STAFF | 创建账号；STUDENT类型同时创建学生资料 |
| POST /sys-user/updateMsg | STUDENT | 修改本人学生联系方式 |
| POST /sys-user/updateMsgAdmin | STAFF | 修改指定学生资料 |
| PUT /sys-user/updateInfo | 已登录 | 修改当前账号姓名或密码，拒绝修改账号名/身份绑定 |
| DELETE /sys-user/delete | 已登录 | 停用当前账号，不删除学生资料 |

旧 /user/login、/user/adduser、/user/updateMsg、/user/updateMsgAdmin 不再支持；学生和管理端已经更新调用。STAFF 仅是教职工类型，不等同已实现细分管理员权限。后续接入 RBAC 时需将注册和代改资料限制到对应管理角色。账号创建不再匿名开放，现有教职工账号迁移后可以登录进行创建。

## 登录

请求示例：

```json
{"username":"20260001","password":"学生密码","accountType":"STUDENT"}
```

管理端发送 accountType=STAFF（省略时默认STAFF以兼容已有管理端调用）。此字段是预期身份，身份判定以数据库为准。返回 data.token、data.userMsgVO（账号资料）；学生另返回 data.studentMsgVO（学生资料）。前端两个会话键升级到v2，旧会话需要重新登录。

令牌含 identityVersion=2、sysUserId、accountType；学生还含 studentUuid。每次请求查 sys_user，校验启用状态及身份绑定；备案仍使用 student.uuid，不能用 sys_user.id 代替。旧版本令牌拒绝使用。现有JWT签名密钥配置方式未调整。

## 学生注册

```json
{
  "username":"20260001",
  "password":"Initial@123",
  "accountType":"STUDENT",
  "student":{
    "studentNo":"20260001",
    "name":"测试学生",
    "idCard":"330302200001011234",
    "college":"计算机学院",
    "major":"软件工程",
    "className":"软件工程2601班",
    "graduationYear":2030,
    "enrollmentYear":2026,
    "educationLevel":"本科",
    "studentStatus":1,
    "classId":1
  }
}
```

学生账号必须等于学号；学生ID由数据库生成，客户端不能绑定已有他人的学生ID。事务调用 StudentService.addStudent，随后按唯一学号查询ID，写入 sys_user.student_uuid。任何失败回滚两表。新注册必须显式提供密码，不再使用身份证后六位。教职工注册继续使用 username/password/realName/counselorId，accountType=STAFF，不携带student。

## 数据库切换（未自动执行）

1. 备份业务数据库，停止旧版本服务写入。
2. 执行 sql/unified_account_01_migrate.sql。先检查学号重复、与管理账号重名、旧密码格式。添加关联与类型字段；现有账号为STAFF，学生账号按学号新增，原MD5仅复制到sys_user并标记MD5。学生旧密码列暂改为可空。
3. 启动新后端，验证原教职工和学生能登录、注册生成双表记录、学生修改资料和备案仍正确。
4. 执行 sql/unified_account_02_drop_legacy_password.sql，删除学生旧密码列。新代码及内存数据库测试均不依赖此列。

DDL会隐式提交。迁移不是幂等脚本；如中断，检查结构并从备份恢复或人工继续，不能直接重复跑。用户名冲突必须先人工处理，脚本不会覆盖已有账号。无明文密码也能保留旧学生登录：先验证旧MD5，成功后用本次输入的密码改存BCrypt，使用条件更新避免覆盖并发改密。不能把MD5再次BCrypt当作原密码。
