# 辅导员班级接口接入

已使用：
- POST /counselor/SelectCounselorByPage，遍历分页获取辅导员。
- GET /class/page、/college/page、/counselor-class/page，每页100条遍历后组合显示。
- POST /counselor-class/add，提交 {counselorId,classId,roleType:1}。
- DELETE /counselor-class/{id}，id为关联记录ID，非班级ID。

未绑定定义为没有任何辅导员关系，已绑定定义为当前辅导员的关联。新绑定默认为主辅导员。多个班级依次调用单个新增接口，遇到失败停止后续提交，显示成功数量和失败原因，刷新实际数据；不是原子批量事务。

建议补充以下接口（路径仅建议，尚未调用）：
1. GET /counselor-class/unbound-classes?pageNum=1&pageSize=10&keyword=...，返回 PageResult<ClassPO>，后端排除所有已关联班级。
2. POST /counselor-class/batch-bind，请求 {counselorId,classIds,roleType:1}，明确全部成功或逐项结果。
3. 辅导员分页增加搜索、totalCount及绑定班级数；按辅导员查询班级增加分页和relationId、roleType，减少全量加载。

当前后端仅防止同一辅导员重复绑定同一班级，允许不同辅导员绑定同一班级。如果业务要求每班仅一个主辅导员，需要后端在加锁事务内检查主辅导员是否已占用，避免并发竞争；前端筛选不能代替该校验。

本次不修改后端。列表搜索为前端对已加载数据筛选，大规模数据应补充上述分页接口。已配置离职辅导员禁止新增绑定。测试使用模拟接口，不写入真实数据库。
