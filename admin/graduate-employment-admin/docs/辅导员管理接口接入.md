# 辅导员管理接口接入

页面：`src/views/CounselorManagementView.vue`。请求模块：`src/api/counselor.js`。

沿用现有管理端视觉规范：主色 #244c8b、正文 #202c40、辅助文字 #58667c、背景 #f4f6fa、分隔线 #e1e6ee；使用现有中文字体、页面标题和表单间距。桌面采用名单表格，700px 以下使用纵向资料列表。使用 Element Plus 弹窗与焦点管理，保存错误保留输入，关闭未保存表单需确认。

## 使用现有接口

- POST `/counselor/SelectCounselorByPage`：请求 `{pageNum,pageSize,start,total:0,totalCount:0}`，其中 start 按页码计算。期望 ResponseVO.data 为 CounselorVO 数组。
- POST `/counselor/add-counselor`：提交 counselorNo、name、gender、phone、email、hireDate。
- PUT `/counselor/UpdateCounselot`：提交 id、gender、phone、email、status，保持后端现有拼写；工号、姓名和入职日期只读。
- DELETE `/counselor/DeleteCounselor/{id}`：后端标记为离职，前端确认框明确提示保留资料。通过编辑状态可恢复在职。

所有请求带 Bearer Token，401 清除会话，403 显示无权限。无总数接口，因此只使用上一页/下一页，不展示虚构总数。搜索只筛选当前页并在输入框明确标注。

## 当前后端阻塞（未修改后端）

CounselorController.SelectCounselorByPage 调用了 `counselorService.PageSelect(pageQuery)`，但忽略返回值，仅返回“查询辅导员成功”。需要由后端将查询返回的 List<CounselorVO> 放入 ResponseVO.data。列表未修复前，页面显示可重试错误，不显示假数据或错误的空列表。

建议将该方法中的两行改为：

```java
return getSuccessResponseVO(counselorService.PageSelect(pageQuery));
```

账号绑定页面仍为独立静态演示，未将示例绑定数据混入真实辅导员名单。
