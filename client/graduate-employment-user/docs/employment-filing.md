# 就业备案页面

沿用现有 PingFang SC / Microsoft YaHei 字体，标题28px、分区标题21px、正文14px。主色 #244c8b，深蓝 #17345d，正文 #202c40，次要文字 #58667c，背景 #f4f6fa，白色工作区。采用左对齐的分组表单和独立填报须知；状态页突出当前阶段，详情只读。移动端单列，表单关联标签，按钮和输入框至少44px，校验错误集中提示并聚焦。动画仅使用组件的加载和对话框反馈。

## 已接入接口

- POST /employment-filing/AddEmploymentFiling：仅提交 AddEmployDTO 支持的表单字段。
- GET /employment-filing/getLastFiling：只有成功返回 data=null 才显示新增表单；查询失败不能当作无记录。
- GET /employment-filing/getFilings：历史列表按服务端顺序展示，可查看只读详情。

提交前再次查询最新记录；已有任意记录时切换为进度页。不支持直接修改记录。预览模式可填写但不能发送真实提交。请求失败后保留输入；添加请求结果不明确时先查询核实，不直接重交。后端确认成功后即使查询失败也保留成功标记，禁止再次提交。

## 后端待补充（本次未修改后端）

- 材料上传接口；现有添加服务将 materials 固定为 []。
- 审核记录查询接口，包括意见、时间、审核人和打回阶段。
- 变更及打回重提接口；最新记录 VO 也未返回备案 ID，不能关联原备案。
- 毕业去向、单位性质、行业字典及对应编码；当前不自行定义编码或提供不匹配的选项。
- 添加服务未设置 applicationNo、destinationType，DTO 也无这两个字段。如果数据库使用 sql/employment_filing.sql 的非空定义，插入会失败，需要后端确认。
- 前端防重复不能替代服务端审核中唯一约束和并发校验。

进度只使用返回的 status；不虚构审核意见或时间。创建时间标注为记录创建时间，不冒充审核时间。状态40不显示已完成的审核阶段，因为接口未提供打回节点。
