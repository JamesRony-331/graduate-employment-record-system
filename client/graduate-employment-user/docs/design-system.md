# 学生端统一设计规范

## 范围与现状

现有 Vue 3 + Vite + JavaScript 项目，无既有路由或业务页面。后端统一登录为 POST /sys-user/login，参数 username/password/accountType=STUDENT；返回 data.token、data.studentMsgVO。修改资料为 POST /sys-user/updateMsg，Bearer Token，学生可修改 phone/email。尚无资料查询接口，使用登录快照，重新登录刷新学校维护的信息。不修改现有后端或管理员端。

## 三个 Skill 的分工

frontend-design 主导视觉；ui-ux-pro-max 检查交互与响应式；frontend-skill 用于组件组织、样式克制及统一性。该同名技能主要提供设计约束，不将其误称为 Vue 编码标准。代码采用现有 JavaScript、Composition API、script setup，以项目架构和可访问性为先。

## 统一视觉

校园学生档案的秩序感，深蓝与留白。避免仪表盘假数据、装饰卡片堆叠和营销式首页。
色彩：主色 #244c8b；深蓝 #17345d；底色 #f4f6fa；白色 #ffffff；正文 #202c40；次要文字 #58667c。错误用 #b42332。
字体：正文 PingFang SC / Microsoft YaHei / sans-serif；登录展示标题 Songti SC / SimSun / serif。正文14–16px，页面标题28px，登录展示标题48–64px。
间距采用8px节奏，表单控件44px高，细边框、8px圆角；主内容最大宽度1120px。

登录：[系统标识 / 校园拱门线稿 / 系统名称] | [学号 / 密码 / 登录]
应用：[系统标识 | 首页 / 备案 / 校招 / 公告 | 个人中心 / 退出]
个人中心：[身份摘要与侧导航] | [学籍资料（只读） / 联系方式 / 编辑入口]
资料编辑：同一布局内双列表单，小屏单列；学籍资料由学校维护。

## 交互与实现

首页为学生服务工作台：个人问候、基于真实资料的联系方式提醒、备案入口及流程说明、公告占位、个人中心与AI服务入口、校招入口。未接入数据的业务统一标记待开放，不伪造备案状态、岗位、公告或统计数量。备案流程的步骤是办理说明，不代表个人审核进度。其他模块显示占位。个人中心与编辑使用独立路由。拆分布局、视图、会话存储与API层。sessionStorage仅保存白名单资料和令牌，不保存密码和身份证。
登录失败保留学号、显示错误；请求禁重复提交，15秒超时；401/403清会话回登录。保存成功后才更新资料，失败保留编辑值。离开未保存页面时确认；会话失效不阻拦回登录。
开发环境提供明确标识的独立演示入口，不发送模拟数据给后端，生产环境不开放。尚未填写的联系方式可保持为空；已有手机号、邮箱仅支持替换，不支持清空（后端Mapper忽略空字符串），保存前明确校验并提示。
支持375/768/1024/1440px；小屏导航可横向滚动，表单单列。可见焦点、关联标签、错误摘要、键盘操作、减少动画偏好。只对交互状态使用短过渡。

## 检查

构建、接口响应与资料验证单测；浏览器验证登录失败/成功、导航、编辑校验、保存失败/成功、离开确认、会话失效、退出、刷新和小屏溢出。真实数据库联调需要可运行后端与有效学生账号，不把拦截接口测试当作真实联调。
