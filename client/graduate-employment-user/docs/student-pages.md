# 学生端页面

## 启动

在本目录执行 `npm install`、`npm run dev`。打开终端给出的地址，默认 http://127.0.0.1:5173/。

- 登录：`/#/login`
- 学生工作台首页：`/#/`，包含联系方式提醒、备案入口及流程、公告占位、常用服务与校招入口。
- 个人中心：`/#/profile`
- 修改联系方式：`/#/profile/edit`
- 就业备案、校园招聘、公告、账号安全为占位页。

开发环境登录页提供“预览页面（示例资料）”。此模式有常驻提示，仅在 sessionStorage 保存示例联系方式，不调用后端；生产构建不提供该入口。

## 接口

开发服务器把 /api 代理至 http://127.0.0.1:5050。后端需单独启动，并使用数据库中已有的学生账号登录。

- POST /api/sys-user/login：username（学号）、password、accountType=STUDENT；读取 data.token 与 data.studentMsgVO。
- POST /api/sys-user/updateMsg：phone、email；Authorization: Bearer token。
- 业务响应 code=200 才视为成功；401/403/901 清会话并返回登录。
- 没有独立资料查询接口，展示登录快照；学校更正学籍资料后重新登录刷新。
- 修改界面仅编辑手机号、邮箱；不向学生暴露修改姓名、学号、学院等权限。
- 后端更新会忽略空字符串，所以已有联系方式只允许替换，清空时显示错误；原本未填写的字段可继续留空。
- 登录密码不保存；会话资料不包含身份证、密码散列。
- 生产部署需要在 Web 服务器配置 /api 反向代理，Vite 开发代理不包含在 dist 内。

## 验证

`npm test`：业务失败响应、联系方式校验、敏感字段过滤。
`npm run format:check`：代码格式。
`npm run build`：生产构建。

浏览器检查使用拦截接口覆盖登录失败/成功、保存失败/成功、取消修改、会话过期、刷新和退出；同时检查375/768/1024/1440px布局。这不等同于真实数据库联调，后者需使用有效账号单独完成。
